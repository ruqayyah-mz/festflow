02Creating an event (organizer)

Create and Edit Event now cover everything needed to run the event:

SettingOptions & rules
Event typeHackathon, Competition, Workshop, Conference/Talk, Meetup, Cultural, Sports, Fun/Social, Other. Shown as a badge and used for filters.
ParticipationSolo or Teams with min/max size (validated, max 10). Can't switch solo↔team once people register.
LocationOnline (venue becomes a meeting link; no QR check-in) or In person.
Registration windowsSeparate optional deadlines plus a "Close now" switch for participants and volunteers. With no deadline, both close when the event starts.
Evaluation roundsRound weights must total exactly 100%. A live total turns red and blocks saving otherwise.
Volunteer recruitmentPrivate links (one per role) or open applications using a custom application form (Google Forms–style: short answer, paragraph, multiple choice, required).

03Running an event (organizer workspace)

Participants tab

  • Applications panel: accept or reject teams and solo entrants.
  • Rosters, tables, check-in and stats count accepted teams only.
  • Registration open/close switch with the closing date.
  • Submissions show screenshots, links, tags and technologies.

Volunteers tab

  • Applications show form answers, the volunteer's profile and FestFlow history.
  • Task status is read-only for organizers (volunteers update it). Organizers Verify finished tasks.
  • "General" tasks can be claimed by any volunteer.
  • Application close switch; real-camera QR check-in.

Judging tab

  • Criteria editor: name each criterion and its points. Must total 100.
  • Leaderboard: per-round judge averages, weighted final out of 100, medals, tie ranks, track filter, "partial" flags.
  • Judge links scoped by table and a real track (dropdown).

After the event ends

  • Everything becomes read-only, enforced in the data layer too.
  • Download Report: stats, final standings, teams, volunteers, sponsors, tasks and the attendance log.
  • Task progress shows 100%.
  • Organizers get notifications for new applications.

04Volunteers & participants

Volunteer journey

Browse Events (type filter)→Fill organizer's form→Accepted (notified)→My Events: ongoing / upcoming / past→Event: Tasks · Announcements · My Profile (QR)
  • Join by link: paste a private invite link (or token) on the dashboard to join a "My Team" event directly. No approval needed, since the link is the approval.
  • Tasks: take up open tasks, update status, release unfinished ones, and see "Awaiting verification" or "Verified".
  • My Profile (sidebar): a proper profile page (headline, about, skills, roles, languages, experience timeline) with an Edit button. First-timers still have something to show.
  • Notification banner for decisions, new tasks, verifications and announcements.

Participant journey

Explore Events (type filter)→Register→Create / join / open team→Lead submits application→Accepted→Submit project
  • Event workspace: Overview (event details + My Team), Submission, Announcements.
  • Teams: join by code or click "Join this team" on teams marked open to new members. The lead can remove members; anyone can leave; you can unregister.
  • Solo events: registering is the application. No team screens.
  • Submission: project name, up to 5 images (auto-compressed), YouTube / website / repo links, description, tags, technologies, additional info.
  • Participants never see scores or rankings. Results are organizer- and judge-only.

05Judging & the scoring math

Judge portal

  • One tab per round, with progress (scored / total) and the current round marked.
  • Each criterion is scored 0 to its own max; totals are out of 100.
  • Save button per project, plus autosave. Edits are never lost on leaving.
  • Offline queue syncs when the connection returns.

How the final score works

1. Each mark → % of what it was scored out of.
2. Average the judges' % for each round.
3. Final = Σ (round average × round weight).

Example: 89/100 in a 35% round contributes 31.2 points. Scores are recalculated and capped on the data side, so a tampered screen can't inflate them.

06Rules the system now enforces

All of these are checked in the data layer, not only hidden in the UI.

RuleEffect
Past events are read-onlyEvery write is refused once an event ends (31 checks across all write paths).
No double rolesNobody can be a participant and a volunteer at the same event.
Team limitsFull teams can't be joined; teams below the minimum can't apply or submit; one team per person per event.
Approval before submittingOnly accepted teams or entrants can submit, check in or be judged.
Sign-up windowsDeadlines and "Close now" stop new registrations, applications and invite joins (invites still work during a live event unless closed).
Totals of exactly 100Round weights and judging criteria both must add up to 100.
Who changes whatOnly the assignee updates a task; only organizers verify; only team leads apply or remove members.
